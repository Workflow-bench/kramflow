# KramFlow — Round 3: Dead-Button Audit + UI Simplification Pass

**Method:** Every route was walked control-by-control with real browser automation (not static reading) — each button, toggle, dropdown, keyboard shortcut, and form was actually clicked/activated and its effect verified against network requests, DOM state, cross-tab sync, and (for the Notes bug) direct Postgres inspection. Where a click appeared to do nothing, it was retried via a direct DOM-level dispatch before being logged as a real defect — several apparent dead buttons turned out to be a quirk of the automation tool's coordinate-click/key-name mapping, not the app; those are called out inline so they aren't mistaken for findings.

**De-duplication:** Per the prompt, Round 1 (`QA_REPORT.md`) and Round 2 (`QA_REPORT_ROUND2.md`) confirmed bugs were **not** re-tested — they're only referenced where directly relevant (the Green Room/General alert gap, the Force Fullscreen root cause, the double-submit guard pattern). Two exceptions where re-encountering a known issue was unavoidable mid-flow are marked accordingly. Everything else below is new to Round 3.

## 2. Clutter/Necessity Findings

| Route | Element | Why flagged | Recommendation | Priority |
|---|---|---|---|---|
| `/green-room` | "Mark Speaker Ready" interactive toggle | `docs/DESIGN_SYSTEM.md` states TV surfaces (explicitly named: Green Room, AV) get **"full-bleed, hero typography, zero controls."** This is a literal, functioning touch/click control on a surface the design doc says should have none — it turns a glanceable, 5–15-feet-away display into something someone has to walk up and interact with, which also cuts against the "calm rather than admin panel" intent restated in the Round 3 brief. | This is a genuinely useful feature (letting a performer signal readiness), so the recommendation is **relocate**, not remove: move it to `/remote` (where backstage crew already have hands-on controls) or to the operator dashboard, and let Green Room stay purely observational. | **High** |
| `/av` and `/general` | "LIVE TIMELINE" / "TODAY'S SCHEDULE" — a dense, scrolling, multi-row list of every cue in the session with times and team names | Directly conflicts with two explicit `DESIGN_SYSTEM.md` rules for TV surfaces: **"No tables"** and **"hero typography... calm rather than admin panel."** This is the single densest, smallest-text block of content on any public-facing display in the app — 8+ rows of tabular data simultaneously visible, the opposite of the "glanceable in under 2 seconds" bar the Round 2 persona test used. ## 3. If you only fix 5 things

Ranked across the full three-round backlog (Round 1 + Round 2 + Round 3), by what most directly threatens a live event:

1. **Alerts never reach Green Room or General (Round 1, BUG-1, Blocker)** — re-confirmed still broken in this round while testing `/remote`'s alert control. An urgent "Drama Team, report to Stage Left NOW" posted from anywhere in the app will never reach the two surfaces performers and the general audience actually watch. This is still the single highest-risk item in the whole backlog.
2. **Operator's own Notes editor doesn't show live notes overrides (Round 3, new, Major)** — the operator can't see what note is actually live without leaving to check a TV display, and editing from the wrong (blank/stale) starting point will silently overwrite a real cue note. Quiet but dangerous: it fails exactly when someone's relying on it mid-show.
3. **Test Message is broken on all 4 display types (Round 2 found 3/4, Round 3 confirms 4/4)** — Display Manager's one built-in way to verify a screen is actually receiving commands before the show doesn't work anywhere, removing the safety net the feature exists for.
4. **Force Fullscreen is fundamentally non-functional as a remote command on every display (Round 3 generalization of Round 2's narrower finding)** — not fixable by wiring up more handlers, since the root cause is the browser's user-gesture requirement; the real fix is either removing the button or replacing it with an on-screen prompt the display itself can act on.
5. **AV/General's dense schedule tables undercut the app's core "glanceable" value proposition (Round 3, new)** — not a functional bug, but the two most information-dense public displays contradict the product's own stated design philosophy and the Round 2 persona test's 2-second glanceability bar; worth fixing before event night for the same reason the other four items are — it's what a stressed, distracted person actually sees.
