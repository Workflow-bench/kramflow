## 2. Bug patterns found while fixing a listed item

- **Double-submit guard gap (item 11):** the same missing-`useRef`-guard pattern existed in both the operator's embedded emergency broadcast panel *and* `broadcast/page.tsx`'s own destructive-action confirm. Both fixed.
- **Command re-handling on any registry change (item 6):** `use-register-display.ts`'s effect had no de-duplication, so *any* command delivered to *any* display was vulnerable to being re-handled multiple times during its round-trip window, not just Force Fullscreen. The `handledIssuedAtRef` fix is in the shared hook, so it covers Test Message and Reload too, not just the command that surfaced it.
- **Stale-countdown fallback (item 16):** checked both Green Room and AV (the only two files rendering a raw `timer.isOverrun ? ... : timer.label`) rather than fixing only the one named in the report; both had the identical bug and both are fixed.

No other instances of these three patterns were found elsewhere in the codebase after grepping for each.

## 3. Deliberately not fixed / needs a decision beyond this pass

1. **Session locking / exclusive control (item 3's explicit boundary).** Presence + toast are implemented; a second operator's action still silently overrides the first's Hold. Real session locking is a genuine design decision (who can override whom, how a lock is released, what happens if an operator's tab crashes while "holding" the lock) — guessing at one wasn't in scope for this pass.
2. **Committing the working tree.** All 17+1 fixes above, plus the `.env.example` redaction, are complete and verified in the working tree but **not committed** — this session didn't commit anything, per the standing instruction to only commit when explicitly asked. When you're ready, a single commit (or however you'd like it split) covering `git status` as of this report is the natural next step.
3. **Git history scrubbing for the leaked secrets (item 17's explicit boundary).** Not acted on. The referenced Supabase project is already dead, which limits the practical risk, but the values remain in history. Whether to rewrite history (and force-push, which has its own costs for anyone else with a clone) is your call, not something to be decided unilaterally.
4. **Supabase-level outage simulation (item 4)** was not re-run live in this pass — the MCP tool's write-action classifier blocked the `UPDATE`/`DROP POLICY` calls needed to simulate it, and that denial was respected rather than routed around. Item 4's fix was instead verified via a real (not simulated) failure produced organically by the cookie rotation in item 17 — see the item 4 row above.
